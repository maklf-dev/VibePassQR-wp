# عملیات، امنیت و نگهداری

## دسترسی‌ها

دسترسی‌ها capability محور هستند. مدیر کل همه دسترسی‌ها را دارد. برای نقش‌های سفارشی از User Role Editor استفاده کنید و فقط capability لازم را بدهید.

- `view_ecm_reports`: گزارش‌ها
- `manage_ecm_events`: رویدادها و نوبت‌ها
- `record_ecm_attendance`: ثبت حضور
- `view_own_ecm_attendance`: سوابق خود اپراتور
- `manage_ecm_settings`: تنظیمات مشترک
- `manage_ecm_files`: فایل و تاریخچه
- `manage_ecm_sms`: پیامک
- `manage_ecm_diagnostics`: گزارش پشتیبانی
- `repair_ecm_pages`: حذف و بازسازی برگه‌های افزونه

## Support Log

ثبت لاگ پیش‌فرض خاموش است. فقط برای بررسی خطا فعال شود و پس از پایان پشتیبانی خاموش و پاک شود. فایل‌ها سقف حجم و چرخش دارند و API Key، متن پیامک، شماره کامل، cookie، token و داده فرم در آن‌ها ذخیره نمی‌شود.

## فایل‌ها و پشتیبان

- PDFهای آرشیوی رمز‌شده‌اند.
- پوشه ذخیره دارای فایل محافظ است؛ روی Nginx نیز فایل اصلی رمز‌شده باقی می‌ماند.
- موتور تولید کارت از PDF غیرفعال است و برای هر شرکت‌کننده فایل جدید ساخته نمی‌شود.
- PDF ثابت راهنمای رویداد از URL مدیر خوانده می‌شود و داخل افزونه تکثیر نمی‌شود.
- ZIP تاریخچه شامل اطلاعات شخصی و PDFهای آرشیوی قدیمی است؛ آن را عمومی نکنید.
- حذف بازه و ریست کامل سابقه، داده‌های عملیاتی اعلام‌شده در فرم تأیید را حذف می‌کنند اما تعریف رویداد، نوبت‌ها و تنظیمات را نگه می‌دارند.

## پیامک

در نسخه 0.6.0 سه Transport عملیاتی وجود دارد: Edge API، واسط IPPanel SMS Pro GV و WP‑SMS. در هاست خارج از ایران، مسیر پیشنهادی واسط GV است که پیش‌تر روی همان سایت تست موفق داشته است. Event Card Manager رمز واسط را کپی نمی‌کند و مستقیماً تابع ارسال عمومی همان افزونه را فراخوانی می‌کند.

برای واسط GV، دامنه باید با HTTPS تنظیم شود. مقدار پیشنهادی `https://ippanel.com` است؛ افزونه در صورت HTTP بودن endpoint از ارسال جلوگیری می‌کند تا رمز پنل روی ارتباط ناامن فرستاده نشود.

برای Edge، کلید داخل سورس یا گزارش قرار نمی‌گیرد. روش پیشنهادی نگهداری کلید پس از فراهم‌شدن مسیر ایران:

```php
define( 'ECM_IPPANEL_API_KEY', 'YOUR_ACCESS_KEY' );
```

ثابت باید پیش از خط `That's all, stop editing` در `wp-config.php` قرار گیرد. کلید را در تیکت، تصویر یا فایل گزارش عمومی ارسال نکنید.

اعلان‌های خودکار ثبت‌نام و حضور وارد صف پس‌زمینه می‌شوند. OTP به‌دلیل زمان محدود، فوری ارسال می‌شود؛ مقدار کد فقط به‌صورت هش در جدول OTP نگهداری و در گزارش پیامک پوشانده می‌شود. Worker هر دقیقه صف عادی را پردازش می‌کند. برای سایت پرترافیک، WP‑Cron را با cron واقعی هاست اجرا کنید. وضعیت `accepted` در واسط GV یعنی سرویس درخواست را پذیرفته؛ این API شناسه یا رسید تحویل نهایی برنمی‌گرداند.

## داده و حریم خصوصی

- زمان‌ها با UTC ذخیره و با منطقه زمانی وردپرس نمایش داده می‌شوند.
- IP در تاریخچه فنی به‌صورت HMAC ذخیره می‌شود.
- User-Agent برای گزارش واقعی دستگاه حضور ذخیره می‌شود.
- بازیابی کارت دارای rate limit است؛ OTP مصرف یک‌باره، اعتبار زمانی، قفل مرورگر و محدودیت تلاش دارد و URL کارت بدون grant معتبر دسترسی ایجاد نمی‌کند.
- مهمان فقط کارت خودش و معرف مجموعه کارت‌های ثبت‌نام خود را دریافت می‌کند.

## توصیه عملیاتی رویداد پرتراکم

- Object Cache و PHP OPcache هاست فعال باشد.
- WP-Cron با cron واقعی هاست جایگزین شود.
- پیش از مراسم، QRها، HTTPS، دوربین و زمان نوبت آزمایش شوند.
- برای اپراتورها شبکه پایدار و حساب جداگانه در نظر بگیرید.
- از یک حساب مشترک برای چند اپراتور استفاده نکنید تا گزارش هویت ثبت‌کننده دقیق بماند.
