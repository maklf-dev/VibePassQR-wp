# برنامه آزمون پذیرش کارفرما — نسخه 0.3.0

آزمون را ابتدا روی staging انجام دهید. برای هر سناریو نتیجه «موفق / ناموفق / انجام نشد»، دستگاه، مرورگر، زمان و تصویر خطا را ثبت کنید.

## ۱. ارتقا و داده‌های قدیمی

- نسخه 0.3.0 را روی نسخه قبلی نصب کنید.
- انتظار: افزونه فعال شود و خطای PHP یا صفحه سفید دیده نشود.
- یک کارت و QR قدیمی را باز و اسکن کنید.
- انتظار: شناسه، کارت و QR قدیمی همچنان معتبر باشند.

## ۲. رویداد و فرم

- رویداد رایگان بدون پرداخت بسازید.
- فرم متنی، تلفن، انتخابی و مهمان را آزمایش کنید.
- رویداد را غیرفعال کنید.
- انتظار: تمام مسیرهای عمومی رویداد پیام غیرفعال سفارشی را نمایش دهند.

## ۳. ثبت بدون درگاه

- رویداد مالی را روی «ثبت بدون درگاه» قرار دهید.
- انتظار: کارت صادر شود و گزارش وضعیت «ثبت‌شده بدون درگاه» نشان دهد؛ وضعیت نباید «پرداخت بانکی موفق» باشد.

## ۴. معرف و مهمان

- یک معرف با حداقل دو مهمان ثبت کنید.
- انتظار: برای هر نفر کارت، QR و کد مستقل ساخته شود.
- با موبایل معرف بازیابی کنید؛ همه کارت‌ها باید نمایش داده شوند.
- با موبایل مهمان بازیابی کنید؛ فقط کارت همان مهمان باید نمایش داده شود.
- چاپ تکی و، در حالت دسترسی گروهی، چاپ همه کارت‌ها را بررسی کنید؛ هر کارت باید روی صفحه مستقل قرار بگیرد و هیچ دکمه PDF تمپلیت نمایش داده نشود.

## ۵. پنل اپراتور

- با نقش مدیر ثبت حضور از `/event-panel/` وارد شوید.
- QR معرف را اسکن کنید؛ معرف و همه مهمانان باید نمایش داده شوند.
- QR مهمان را اسکن کنید؛ فقط همان مهمان باید نمایش داده شود.
- ثبت یک نفر، همه و انتخاب گزینشی را آزمایش کنید.
- انتظار: پس از تشخیص، تصویر ثابت شود؛ پس از ثبت موفق یا دکمه اسکن مجدد، دوربین دوباره آماده شود.
- همان فرد را دوباره ثبت کنید؛ انتظار: ثبت تکراری ایجاد نشود و زمان/اپراتور قبلی نمایش داده شود.

## ۶. دسترسی

- کاربر عادی، اپراتور مجاز، مدیر گزارش و مدیر کل را جداگانه آزمایش کنید.
- انتظار: هر نقش فقط بخش‌های دارای capability را ببیند.
- اپراتور غیرمجاز یک رویداد نباید lookup یا ثبت حضور انجام دهد.

## ۷. گزارش و خروجی

- فیلتر رویداد، نوبت، تاریخ، پرداخت و جست‌وجو را بررسی کنید.
- انتخاب همه/هیچ‌کدام ستون‌ها را بررسی کنید.
- CSV و سند چاپ را با همان ستون‌های انتخاب‌شده مقایسه کنید.
- پروفایل شخص، مهمان، اپراتور و رویداد را از لینک جدول باز کنید.
- دستگاه فقط در صورت وجود snapshot واقعی نمایش داده شود.

## ۸. موبایل و مرورگر

حداقل روی Chrome Android، Safari iPhone، Chrome دسکتاپ و Firefox دسکتاپ آزمایش کنید. ثبت‌نام، کارت، PDF، پنل اپراتور و گزارش نباید اسکرول یا دکمه غیرقابل‌استفاده داشته باشند.

## قالب گزارش خطا

- بخش و سناریو
- URL بدون اطلاعات حساس
- نقش کاربر
- رویداد و نوبت
- دستگاه و نسخه مرورگر
- زمان دقیق رخداد
- انتظار و نتیجه واقعی
- تصویر صفحه
- در خطای فنی: فایل JSON بخش نگهداری و عیب‌یابی، بدون API Key یا شماره کامل کاربران
