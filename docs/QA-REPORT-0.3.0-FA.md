# گزارش کنترل کیفیت Event Card Manager 0.3.0

تاریخ ساخت: ۱۴ اکتبر ۲۰۲۶

## نتیجه

بسته انتشار از نظر نحو، ساختار، قراردادهای سازگاری، امنیت اطلاعات حساس و یکپارچگی قابلیت‌های اصلی بررسی شد و همه کنترل‌های خودکار با موفقیت عبور کردند. نسخه برای نصب آزمایشی روی staging و اجرای برنامه پذیرش کارفرما آماده است.

## کنترل‌های موفق

- parse مستقل ۲۲ فایل PHP
- parse شش فایل JavaScript، شامل decoder محلی QR
- توازن ساختاری سه فایل CSS
- تطابق نسخه هدر و ثابت افزونه با `0.3.0`
- حفظ قراردادهای قدیمی کوکی دسترسی، grant کارت و امضای HMAC کد QR
- حفظ خواندن QRهای قدیمی و پشتیبانی از QR مستقل مهمان
- کنترل جداسازی دسترسی کارت معرف و مهمان
- کنترل سمت سرور مجوز اپراتور، انتخاب شرکت‌کننده و جلوگیری از ثبت تکراری
- کنترل چرخه دوربین شامل توقف تصویر، اسکن مجدد و شروع خودکار بعد از ثبت
- وجود fallback محلی برای Safari بدون وابستگی به CDN
- بررسی مهاجرت افزایشی و ایندکس‌های دیتابیس
- بررسی پیش‌بارگذاری بسته‌ای گزارش و حذف الگوی Query جدا برای هر سطر
- بررسی تولید بسته‌ای سند چاپ گزارش برای محدودماندن مصرف حافظه
- بررسی عدم وجود کلید API ارسال‌شده، دامنه و IP محیط توسعه در بسته
- بررسی حذف ابزار ریست داده آزمایشی و خاموش‌بودن پیش‌فرض لاگ پشتیبانی
- بررسی نبود پرداخت بانکی موفق ساختگی و استفاده از وضعیت مستقل `offline_confirmed`

## محدودیت محیط ساخت

این کنترل کیفیت جای آزمون واقعی وردپرس، MySQL، مجوز دوربین، Safari/iOS و تنظیمات هاست را نمی‌گیرد. نصب و سناریوهای عملی باید ابتدا روی staging مطابق فایل `EMPLOYER-ACCEPTANCE-TEST-FA.md` اجرا شوند. در این محیط، ارسال واقعی IPPanel و درگاه بانکی نیز آزمون نشده‌اند؛ پیامک عمداً متوقف است و درگاه واقعی در این انتشار پیکربندی نشده است.

## معیار پذیرش نهایی سایت

انتشار روی سایت اصلی پس از این موارد انجام شود:

1. پشتیبان کامل دیتابیس و فایل‌ها تهیه شده باشد.
2. یک کارت و QR قدیمی پس از ارتقا معتبر بماند.
3. ثبت‌نام رایگان، ثبت بدون درگاه، بازیابی معرف/مهمان و چاپ چندکارت تأیید شوند.
4. ثبت پشت‌سرهم با دوربین روی Chrome Android و Safari iPhone آزمایش شود.
5. capability نقش‌ها، گزارش‌ها، CSV و سند چاپ با داده staging بررسی شوند.
