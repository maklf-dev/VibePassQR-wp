# VibePassQR 0.7.0-alpha.7 | فاز هشتم، اصلاحات پایداری و ابزار آزمون

## هدف و مبنا

این نسخه مستقیماً از بسته کامل `0.7.0-alpha.6` ساخته شده و **همان پوشه و شناسه افزونه `event-card-manager`** را دارد. تغییرات این مرحله محدود به مقاوم‌سازی مسیرهای حساس و ابزار تشخیص است. هنوز نسخه پایدار یا تأییدشده برای سایت اصلی نیست.

## اصلاحات انجام‌شده

1. **پیش‌بررسی تراکنش صدور کارت Workflow:** پیش از `START TRANSACTION`، تراکنشی‌بودن ۹ جدول `flow_instances`، `flow_files`، `registrations`، `people`، `participants`، `registration_meta`، `ticket_tokens`، `attendance` و `events` از `information_schema` بررسی می‌شود. نبود جدول، خطای Query یا Engine غیر `InnoDB` عملیات را با کد `ecm_flow_nontransactional_storage` متوقف می‌کند. این محافظ مانع ادعای نادرست Rollback اتمیک برای جدول‌های MyISAM می‌شود. داده شخصی به گزارش خطای این کنترل اضافه نشده است.
2. **تقویت ورود گروهی:** جدول `attendance` به فهرست وابستگی‌های بررسی تراکنش اضافه شد، زیرا مسیر ایجاد هویت می‌تواند رکورد حضور قدیمی را نیز به‌روزرسانی کند. بررسی نام جدول‌ها اکنون باید دقیق، بدون تکرار و با Engine معتبر باشد.
3. **سخت‌گیری روی محدودسازی OTP:** محدودیت مبتنی بر شبکه که در عمل اجازه حداکثر ۱۰۰۰ درخواست می‌داد، به سقف `max(60, 8 × limit)` در هر بازه کاهش یافت. برای OTP با محدودیت ۸، سقف شبکه ۶۴ درخواست در ساعت است. تغییر کوکی مرورگر نباید این سقف را دور بزند. *این ابزار به‌تنهایی جایگزین قفل اتمیک در Object Cache یا محافظ لایه سرور نیست.*
4. **جلوگیری از کش‌شدن صفحه پیگیری:** صفحات حاوی `[ecm_tracking_lookup]` یا `[ecm_flow_tracking]` در صورت فعال‌بودن پیگیری، پیش از رندر با `DONOTCACHEPAGE` و `nocache_headers()` محافظت می‌شوند.
5. **ابزار آزمون مستقل:** سناریوهای منفی برای خرابی Engine و بای‌پس محدودیت شبکه افزوده شدند؛ یک فایل `staging-preflight.php` فقط‌خواندنی و اسکریپت Windows PowerShell بررسی ZIP نیز در بسته مجزای QA قرار دارند.

## مواردی که عمداً تغییر نکرده‌اند

- مسیرهای ثبت‌نام Classic، تاریخچه ثبت‌نام/مهمان، کارت و QR، حضور، صف پیامک و شناسه‌ها
- دیتابیس، جدول‌ها، ایندکس‌ها و داده‌های موجود؛ **هیچ Migration جدیدی در این فاز اضافه نشده است**
- Default-off بودن تمام پرچم‌های Workflow، صدور کارت و ورود گروهی
- پیاده‌سازی UI و کاتالوگ شورت‌کد از فازهای قبل

## محدودیت‌های باقیمانده

- تست PHP Syntax و تست‌های Mock در این محیط اجرا شده‌اند؛ نسخه PHP این محیط 8.4 است و با محیط PHP 8.1 سایت کاربر برابر نیست.
- هنوز به Staging واقعی WordPress/MariaDB، سرویس پیامک و مرورگرهای موبایل دسترسی نیست؛ آزمون تراکنش و Rollback، بارگذاری واقعی رسید و هم‌زمانی دو مدیر **انجام نشده است**.
- این انتشار نباید برای Production نصب شود. تکمیل فاز هشتم منوط به دریافت و بررسی نتایج آزمون‌های محیط آزمایشی است.
