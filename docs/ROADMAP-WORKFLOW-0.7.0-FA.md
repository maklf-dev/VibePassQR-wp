# قرارداد پیاده‌سازی Workflow 0.7.0 | ادامه توسعه پس از 0.6.7

این فایل قرارداد معماری مرحله بعد است، نه فهرست قابلیت‌هایی که اکنون نصب شده‌اند.

## مرز سازگاری

ثبت‌نام فعلی (`ECM_Public`، `ECM_DB`، `ECM_Participants` و `ECM_Tickets`) باید برای رویدادهای Legacy با همان فرایند، جدول‌ها، شناسه‌ها، QRها و لینک‌ها فعال بماند. هر رویداد قابلیت `classic` یا `custom_workflow` داشته باشد؛ برای رویدادهای قدیمی، مقدار پیش‌فرض `classic` است.

## داده‌های جدید

- `ecm_flow_versions`: event_id، version_number، تعریف مراحل به صورت JSON معتبر، تنظیمات قالب، published_at و وضعیت نسخه.
- `ecm_flow_instances`: UUID داخلی، event_id، flow_version_id، current_step_key، state فنی ثابت، شماره درخواست، digest شناسه فرد، اطلاعات فرم پاک‌سازی‌شده، linked_registration_id اختیاری، version برای کنترل هم‌زمانی، زمان ایجاد/انقضا.
- `ecm_flow_files`: instance_id، file_id یا مسیر حفاظت‌شده، MIME معتبر، hash، اندازه، نسخه رسید و وضعیت بررسی.
- تاریخچه وضعیت و پذیرش نسخه‌دار در جدول رخداد موجود `ecm_events` با ارتباط مستقل به instance؛ در صورت نیاز، مهاجرت افزودنی و بدون حذف انجام شود.

## سرویس‌ها

- `WorkflowEngine`: مراحل و انتقال‌های مجاز؛ بررسی سمت سرور با optimistic concurrency.
- `StepRenderer`: HTML مجاز + shortcodes کنترل‌شده برای `field`, `agreement`, `receipt_upload`, `tracking`, `card_access`; عدم اجرای PHP/JS دلخواه.
- `EvidenceService`: اعتبارسنجی فایل، ثبت امن و ارائه فقط با مجوز.
- `ReviewService`: approve/reject/needs_correction با Audit Trail و جلوگیری از تأیید دوباره.
- `RegistrationBridge`: تبدیل درخواست تأییدشده به رکوردهای استاندارد ECM؛ idempotency و Transaction.
- `NotificationBridge`: ارسال پیامک براساس Workflow ID حتی پیش از ایجاد registration_id؛ ثبت کلید یکتا برای هر اعلان.
- `TrackingService`: مشاهده وضعیت با OTP یا مجوز کوتاه‌عمر؛ ممنوعیت مشاهده فایل/کارت فقط با شماره موبایل.

## ترتیب ساخت و آزمون

1. تعریف schema و Migration افزایشی با feature flag خاموش؛ آزمایش نصب و بازگشت روی کپی دیتابیس.
2. نوشتن موتور انتقال وضعیت و آزمایش واحد تصمیم‌های تأیید و رد.
3. فرم‌ساز و پذیرش نسخه‌دار سند و آپلود رسید؛ آزمون امنیت و هم‌زمانی.
4. پیاده‌سازی پنل بررسی، پیگیری و اتصال به ثبت‌نام/QR/SMS فعلی.
5. رندر قابل ویرایش HTML/CSS و کاتالوگ shortcode؛ پیش‌نمایش موبایل/دسکتاپ.
6. آزمون‌های ترکیبی، فشار و سازگاری سپس فعال‌سازی اختیاری فقط روی یک رویداد جدید.

**معیار پذیرش:** تأیید دو مدیر به‌صورت هم‌زمان نباید دو کارت یا دو پیامک بسازد؛ تغییر نسخه میثاق‌نامه نباید درخواست‌های قبلی را به هم بزند؛ بعد از نصب، کارت‌های 0.6.6 باید بدون مهاجرت تخریبی قابل بازیابی بمانند.
